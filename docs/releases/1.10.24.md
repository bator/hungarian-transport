Hungarian transport 1.10.24. Includes fresh Volán and city GTFS indexes.

## Highlights

- **Signed timetables from GitHub Pages.** The daily MÁV index (`mav-index.json`) and the weekly Volán and city indexes (`timetables.json`) are now signed (ed25519, `.sig` next to each manifest). The integration installs an index from Pages only when its manifest's signature verifies against the key it ships with; a missing or bad signature installs nothing and keeps the index you have. Right after a deploy the integration waits out GitHub Pages' cache once before it calls a mismatch a failure.
- **Release indexes win by version.** Pages entries name the release they were built against (`release_version`). A Pages index never replaces the index of a newer release you just installed. A strictly newer Pages index still installs, and an index older than 21 days falls back to the old rule.
- **Why an index was not installed.** `sensor.hungarian_transport_volan_timetable`, `sensor.hungarian_transport_city_timetables` and `sensor.hungarian_transport_daily_mav_check` show `pages_reason` / `reason` (for example `bad_signature`, `unknown_key`, `release_newer`, `mismatch`) and, while a check waits for Pages' cache, `pages_settling`. The notification names the feed day of the city timetables.
- **New option "Ask mavplusz.hu"** (on by default). Off, nothing is sent to mavplusz.hu: trains and buses read only the GTFS-Realtime feeds on jbb.ghsq.de, and a Budapest board FUTÁR cannot answer falls back to Transitous.
- **Steadier trains from mavplusz.hu.** A trip or route the planner rejects holds back only itself: a large request is split, a single failing trip waits (longer each time it fails again), and only a real planner outage backs off the shared limit. A trip with unexpected data no longer takes its whole batch down. After an outage every train is answered again in the first round.
- **BKK boards during a FUTÁR outage.** While FUTÁR is down, the planner is asked first and FUTÁR is probed once every 30 s; a board the planner answered in the last 35 s is served from its cache, and cards asking for the same board at once share one FUTÁR request and token. The log says once per 5 minutes that FUTÁR is down and once that it is back.
- **Safer installs.** A Home Assistant stop during an install waits for it to finish and records it; a stop during a download keeps the verified files, so the next try downloads only the rest.

## Upgrade notes

- Nothing to do. Cards, options and saved stops are kept.
- Timetables from Pages install only from the signed site; it is live since before this release.
