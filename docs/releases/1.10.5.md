Hungarian transport 1.10.5. Fixes from two more code reviews, chiefly for the colour themes and the planner. Includes fresh Volán and city GTFS indexes.

## Fix: colour themes readable in dark mode

- **Cause:** a theme replaced Home Assistant's primary colour with the operator's brand colour, which the planner also uses for text and focus rings. On a dark Home Assistant theme the "Új" button, the map-only button and the focus rings dropped to 1.6–4.3:1 (Bahart 1.6:1).
- **Now:** the theme colours only fills; text and focus rings use a dark-mode-aware shade of the brand colour, and the label on a filled button is black or white, whichever reads better. Every theme now reaches at least 4.5:1 for text and 3:1 for marks, on light and dark Home Assistant themes; a test checks the colours actually drawn. Older app WebViews without `color-mix` get a plain fallback.

## Planner

- **Volán departures on the "Most" board:** a Volán destination picked in the planner's editor saved its lines without the timetable prefix, so every Volán departure was filtered out. Both editors and the planner now save lines the same way.
- **"Most" stays Most:** pressing Now or Reset right after picking a day or time no longer switches back to Depart a moment later.
- **Look-ahead in hours and minutes:** "3 óra 20 perc" instead of "3,3333333333333335 óra".
- **Swap button:** without a destination stop id (older YAML) the swap buttons are disabled instead of doing nothing.
- **Editor:** the "by operator" theme, which the planner cannot use, is no longer offered there.

## Departure card and editor

- **Buses stay on the map:** a single failed coach position lookup no longer removes every carried GPS position for a refresh.
- **Destination list comes back:** after a failed load, the editor loads the destinations again once the key changes (or after 30 seconds).
- **YAML:** `routeIds: 109` (a single number) works; theme ids are case-insensitive (`BKK`), and names such as `constructor` are no longer taken for a theme.

## Integration

- **BKK key:** a slow answer to a request sent before the key was rejected no longer clears the rejection; a FUTÁR answer whose status is not `OK` is an error, not data; a key check that hits BKK's rate limit says so instead of "cannot connect".
- **MÁV index:** after a failed build only the build's own temporary file is removed, never one another writer is still writing.

## Timetable updates and releases

- **MÁV rebuild after an update:** the local updater decides by the index's own build time, so a MÁV feed whose build failed is built again after a HACS update instead of being forgotten.
- **Release diagnostics:** a pfaedle run killed early (for example out of memory) is reported as killed, not as a timeout; a malformed version tag stops the release before anything is built.

## Upgrade notes

- **Restart needed:** restart Home Assistant after updating, then reload the dashboard.
