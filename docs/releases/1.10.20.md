Hungarian transport 1.10.20. A fix release from a full code review: live data on long Veszprém and Miskolc boards, duplicate and vanishing departures on the cards, and a guard against publishing a truncated MÁV timetable.

## Fixes

- **Live data on long Veszprém and Miskolc boards:** a board with more than 20 rows lost delays and vehicle positions for the rows past the twentieth, on every poll, and did not fall back to the jbb.ghsq.de feeds for them. Every row is now asked for, and a row the planner did not answer falls back to the feeds.
- **Wrong direction's delay:** when both ends of a line start at the same minute and only one of the two trips had live data, a row could show the other direction's delay and vehicle. Such a row now has to call at the card's stops, or it gets no live data rather than wrong data.
- **Live data across service days:** yesterday's late run and today's run of the same trip no longer overwrite each other, and a train row is matched only to today's run or last night's.
- **Duplicate departures:** two trips of one line leaving in the same minute were listed twice each. Each trip is now listed once.
- **"No departures" for ten minutes:** on a board filled from Transitous (at night, or on a MÁV card during an ELVIRA gap), one failed request emptied the board and Transitous was not asked again for ten minutes. A failed request now keeps the departures still due, and the "No departures" flash before the fill answers is gone.
- **"BKK [object Object]":** when the connection to Home Assistant dropped, the BKK banner showed `[object Object]` or a bare number. It now shows the reason.
- **Live data off after one dropped connection:** one failed realtime call switched off delays and positions on every card of the page for five minutes. They now pause only after three failed polls in a row.
- **Vehicle map stuck on "live":** a map left open after its departure left the board kept the last GPS position and still said live. It now switches to the timetable estimate.
- **BKK key prompt after a fix:** a "BKK key rejected" prompt stayed after a working key was saved in the integration's options, and submitting it empty removed the key. Saving a working key now closes it.
- **Removing and re-adding the integration:** without a restart in between, the dashboard resource is set up again and the old failed-update notification no longer comes back.
- **Service call errors:** `.inf` in a number field of a service call is now a validation error instead of a traceback, and an ELVIRA row with an out-of-range date no longer fails the whole call.

## Changes

- Fewer repaints of the departure table: rows that did not change keep the table, so tooltips and focus stay put.
- Decoded realtime feeds no card asks for any more are released, and a slow journey planner falls back to the feeds after 20 seconds.
- **Truncated MÁV timetable guard:** a MÁV timetable with under half the trains and lines of the published one is no longer published; the previous one stays. The repository variable `MAV_ALLOW_SHRINK=1` accepts an intended reduction.
- The timetable update script keeps a newer Volán or city timetable shipped with an update instead of restoring its own older copy, and reads a damaged `state.json` as empty instead of failing every run.
- Feed catalog API keys are no longer sent on to another host on a redirect.

## Upgrade notes

- **Restart needed:** restart Home Assistant after updating, then reload the dashboard.
