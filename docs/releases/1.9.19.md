Hungarian transport 1.9.19. Fixes from two more code reviews. Includes fresh Volán, city and MÁV indexes.

## Departure card and editor

- **The right bus station:** picking "Győr, autóbusz-állomás" (or any town's bus station) as the destination in the card editor saved a key without the town, so coaches to *any* bus station (Tatabánya) were listed as if they went to Győr, with the travel time to Tatabánya. The town stays in the key; the planner already got this right.
- **Editor:** after a failed destination load, every keystroke in the name field asked BKK again and showed the error again. It is tried once per stop.
- **City boards:** when a city board is empty and Transitous fills in, the search starts from your stop's coordinates, not from the first "Kossuth tér" in the country.

## Planner

- **New pair, new plan:** choosing another origin or destination in the editor (or a dashboard reload) no longer leaves the previous pair's itinerary, inline map and timeline on screen until the new board arrives, and a map still opening for the old pair cannot paint it over the new one.
- **Map and "Mikor":** changing the time while the itinerary map was opening gave a bare straight line with a "null perc · null átszállás" footer. The map draws the plan it started with, or does not open.
- **Colours:** a bus or tram leg without its own colour is no longer drawn in MÁV blue.
- **Keyboard:** the itinerary map takes focus like the vehicle map, so Tab and Escape work inside it and focus comes back when it closes.

## Integration

- **ELVIRA:** a station code with a stray extra digit is refused instead of silently querying another station; an odd `start` field in MÁV's answer no longer empties the whole board.
- **MÁV route index:** a feed with `stop_sequence` written as `10.0` (or missing) had its stops ordered alphabetically by id, and the audit missed it. Sequence order, or file order, is kept.
- **Permissions:** the built MÁV index is a normal 0644 file (it was 0600 and travelled so into the frontend zip).

## Timetable updates and releases

- **Scripts newer than your card:** if you copied `scripts/` from main after an index-format bump, the daily update wrote an index your installed card could not read ("The timetable index is newer than this card understands") until the next HACS update. The updater now reads the card's format from the installed bundle, skips the rebuild and tells you to copy the installed release's scripts.
- **Feeds with a space after every comma:** such a `calendar.txt` lost whole weekdays silently. Values are cleaned and the weekday mask is always seven digits.
- **Feed size limits:** the uncompressed-member cap sat just above the real Volán `shapes.txt` and would have failed every update once the feed grew. Raised to 2 GiB (members) and 500 MiB (download).
- **Which MÁV index wins:** of two indexes from different feeds, the later *build* wins, read from the file itself, not the time HACS unpacked it. A release built from an older feed no longer replaces your newer build.
- **Change detection:** a server answering HEAD with `Content-Length: 0` no longer counts as "unchanged" for a week.
- **Updates are announced** even when another index failed in the same run.
- **CI:** checkouts in the validation workflow no longer persist the token.

## Upgrade notes

- **Restart needed:** restart Home Assistant after updating, then reload the dashboard.
- **Bus-station destinations:** cards whose destination was picked as a bus station in the editor before this release may carry the town-less key (`destKey: aut all`). Pick the destination again in the editor to fix them.
- **Own `scripts/` copy:** copy `scripts/` from this release (not from main) to `/config/hungarian-transport`.
